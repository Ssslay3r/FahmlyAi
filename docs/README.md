# Fahmly Documentation

These directories organize planning, design, validation, and graduation-project report assets. Most areas remain placeholders; `ui-ux/` now contains a redesign based on the original approved visual references and an interactive local prototype.

- `requirements/`: Software Requirements Specification, functional and non-functional requirements, use cases, and user stories.
- `architecture/`: system architecture, component boundaries, and design decisions.
- `database/`: database design, entity descriptions, relationships, and ERD documentation.
- `api/`: shared FastAPI API contracts and endpoint documentation for both clients.
- [ui-ux/](ui-ux/README.md): branding, mascot assets, colors, typography, design-system guidance, wireframes, mobile/web interface designs, and prototypes, including Arabic support.
- `testing/`: test strategy, test plans, cases, and validation reports.
- `ai-rag/`: RAG architecture, prompt design, retrieval approach, and AI evaluation documentation.
- `deployment/`: environment planning, setup instructions, and deployment documentation.
- `diagrams/`: UML, system architecture, ERD, and other diagram source/export assets.
- `project-management/`: team responsibilities, milestones, backlog, and graduation-project report planning and assembly assets.

Report sections can reference the relevant topic directories; overall report organization belongs in `project-management/`.

The next phase should establish system requirements and UI/UX before initializing Flutter, Next.js, and FastAPI applications. Keep the design appropriate for a four-person team and an approximately 12-week delivery window.
