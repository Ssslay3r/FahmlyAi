# User flows and screen structure

The [prototype](../prototypes/index.html) presents these flows in the approved visual language. They are design demonstrations, not connected application features.

1. Onboarding: meet Rafeeq, understand document-based studying, then enter Home.
2. Home: welcome/hero, upload or chat actions, four study shortcuts, recent documents, and study-progress context.
3. Upload: documents page, select an example or a local filename, processing, reading, and ready state. No file bytes leave the browser.
4. Study: document details, Summary / Key Points / Topics, contextual chat, then citations back to the document.
5. Practice: quiz setup, three example questions, immediate constructive feedback, results, answer review, retry or return to the material.
6. Preferences: profile, language, theme, and standard Arabic / Libyan conversational preference.
7. Failure recovery: prototype controls demonstrate an error with retry and offline with reconnect.

Desktop uses a sidebar and workspace. Phone uses a single column and five bottom-navigation destinations. Arabic mirrors the structure. Authentication and remaining account flows require separate requirements and wireframe review before production work.
